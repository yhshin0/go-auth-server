# ADR-010: password hashing algorithm

- **Status**: Accepted
- **Date**: 2026-05-07

## Context

패스워드 해싱을 위한 알고리즘 선택이 필요하다.

선택 가능한 알고리즘은 다음과 같다.

||bcrypt|scrypt|Argon2id|
|---|---|---|---|
|출시 연도|1999년|2009년|2015년|
|주요 특징|CPU 집약적. 반복 횟수(Work Factor)를 조절해 연산 시간을 늘림.|메모리 집약적. 다량의 메모리를 요구해 하드웨어 공격을 방어.|하이브리드. 시간과 메모리 비용을 모두 제어하며 부채널 공격 방어.|
|강점|단순하고 검증됨. 레인보우 테이블 공격에 매우 강함.|GPU 및 FPGA(맞춤형 하드웨어)를 이용한 대규모 공격에 저항력이 강함.|최신 표준. 사이드 채널 공격과 GPU 병렬화 공격 모두에 대해 가장 강력함.|
|약점|GPU를 활용한 병렬 연산 공격에는 상대적으로 취약할 수 있음.|설정이 복잡하며, 과도한 메모리 사용 시 서버 성능에 영향을 줄 수 있음.|구현이 상대적으로 복잡하고 라이브러리 지원이 다른 둘에 비해 적을 수 있음.|

## Decision

**Argon2id 채택**

### Argon2id 선택 이유

- 최신 표준 알고리즘
- 사이드 채널 공격과 GPU 병렬화 공격 모두에 대해 가장 강력
- 메모리(m)와 시간(t)이 분리되어 있어, 유연한 튜닝이 가능

### 기타 알고리즘을 선택하지 않은 이유

- **bcrypt**: 가장 널리 사용되지만, 메모리 제약이 없어 GPU 병렬화 공격에 상대적으로 불리
- **scrypt**: 파라미터 간의 강한 의존성. 부채널 공격 방어에 취약

### 한계

- 파라미터 설정에 따라 서버에 부하가 커질 수 있음
  (e.g. 서버 메모리 1gb, m=65536 설정 시, 100명이 로그인에 동시 접근한다면 OOM이 발생할 수 있음)

## Consequences

- argon에 대한 적절한 파라미터 세팅이 필요
- 해싱을 사용하는 수를 관리할 필요성이 있음
